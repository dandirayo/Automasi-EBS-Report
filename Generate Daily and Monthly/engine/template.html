📖 Glosari Istilah Kunci (Perspektif Akuntansi & IT / Developer)

🏛️ Glosari Divisi Akuntansi (Accounting Concepts)

  • XLA (Subledger Accounting): Mesin akuntansi sentral Oracle yang memetakan transaksi bisnis hulu menjadi jurnal standar sebelum masuk ke General Ledger.
  • FAH (Financial Accounting Hub): Gerbang penerima data dari berbagai aplikasi eksternal (ICONS, Credit Card, dll) untuk validasi format sebelum diproses akuntansi.
  • Accounted vs Not Accounted: Accounted adalah transaksi yang sukses dibuatkan jurnal debit-kreditnya. Not Accounted adalah data yang lolos validasi tetapi jurnalnya belum terbentuk (menunggu sweep atau aturan jurnal spesifik belum terdefinisi).
  • XLA Error vs Event Unprocessed: XLA Error adalah transaksi gagal diproses (misal: Kurs Closing valas belum ada / intercompany selisih). Unprocessed adalah antrean transaksi wajar yang sedang menunggu giliran batch.
  • Posted vs Unposted GL: Posted berarti jurnal telah resmi membukukan saldo neraca/laba-rugi. Unposted berarti jurnal sudah ada di GL namun pembukuannya tertunda/hold.

💻 Glosari Tim IT & Developer (Technical & Reliability)

  • Concurrent Program / Manager: Komponen latar belakang Oracle EBS yang menjalankan program batch otomatis, ETL data, dan laporan terjadwal.
  • P95 / P99 Latency (Persentil): P95/P99 mengukur waktu penyelesaian untuk 95% atau 99% request tercepat. P99 adalah tolok ukur utama durasi terburuk (*worst-case*) guna mendeteksi bottleneck.
  • CPU Saturation (>80% / >90%): Kondisi saat prosesor server kehabisan kapasitas komputasi, yang dapat memicu antrean Concurrent Manager memanjang dan transaksi tertunda.
  • Parent & Child Request: Program induk (seperti Create Accounting) yang otomatis meluncurkan beberapa proses pekerja cabang (seperti Accounting Program) secara paralel.
  • Sweep Process: Siklus batch pembersihan untuk menyapu transaksi-transaksi menggantung pada akhir periode agar tidak tertinggal ke periode akuntansi berikutnya.

📖 Glosarium Alur Pemrosesan Akuntansi End-to-End (Data Pipeline EFS)

Panduan tahapan siklus data transaksi dari aplikasi sumber (Intake) hingga resmi terbit dan dibukukan ke General Ledger (GL).

1. INTAKE
Masuk FAH: File staging dari apps hulu.
2. FAH PROCESS
Validasi Format: FAH Success vs Error.
3. XLA EVENT
Registrasi: Event Class & Stuck XLA.
4. SLA ACCOUNT
Create Account: Accounted / Not Accounted.
5. TRANSFER GL
Interface GL: Pengiriman jurnal accounted.
6. GL IMPORT
Journal Import: Pembentukan header & line GL.
7. GL POSTING
Posting Final: Posted vs Unposted.
📌 Tahap 1 - 4: Validasi & Pembentukan Jurnal Subledger (SLA)
  • Masuk FAH (Intake): Volume data mentah transaksi hulu yang berhasil masuk ke staging table FAH.
  • FAH Processing (Validasi Format): Data divalidasi struktur file & header-nya. Sukses masuk antrean = FAH Success, data cacat = FAH Error.
  • Event Class & Entity: Klasifikasi jenis transaksi (misal: DEP = Simpanan/Tabungan, LON = Kredit/Pinjaman, INVV = Invoice Voucher). Data yang terhambat di status event masuk kategori Stuck in XLA atau Entities Invalid.
  • SLA Accounting (Create Accounting): Proses penerjemahan event menjadi jurnal Debit-Kredit. Data lolos validasi tapi belum membentuk jurnal disebut Not Accounted (menunggu batch sweep / aturan akuntansi).
📌 Tahap 5 - 7: Pengiriman & Pembukuan Buku Besar (GL)
  • Transfer to GL: Pemindahan jurnal yang sudah accounted dari tabel subledger ke antarmuka General Ledger (GL_INTERFACE).
  • GL Journal Import: Program batch yang mengimpor data antarmuka menjadi entri jurnal General Ledger resmi siap posting.
  • Posted GL: Jurnal yang telah resmi diposting dan membukukan perubahan saldo pada buku besar (GL_BALANCES).
  • Unposted GL: Jurnal yang telah berada di modul GL namun status postingnya masih tertunda (pending post / menunggu persetujuan period close).
